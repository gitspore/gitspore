# 2026-10-06: App layout for v3

Ticket: #1 (GSP-1). Process record.

## What happened

We discussed the app layout for concept v3. Georgios sketched the layout and its states in Penpot (frames: default, scene only, terminal maximised, tiled terminals, issues tab, issue selected). The sketch was the starting point; the export is not in the repo.

## What we did

- Wrote `concept/v3_layout.html`: layout model, 16 wireframed states (S01–S16), ways to act, user stories, components, limits, mapping to the open tickets and 12 proposed new tickets (N1–N12).
- Moved the branch graph from an overlay over the scene into a **Branches** tab of the side panel, with a status dot on each branch label.
- Updated `concept/v3_planter-grid.md` to match: garden map section, "Next to the scene", must-have, should-have and later lists.
- Built a live 3D prototype of the layout, `research/inspiration/renders/planter-grid-layout.html`. It reuses the scene of `planter-grid.html` and has a picker for all 16 states.
- Took screenshots of every state and both styles for a presentation: `concept/v3_layout-slides/`.

## Proposed, not decided

- Windows sit in fixed slots and are sized by buttons only (minimise, maximise, focus this, close). No dragging.
- The scene always fills the page; the camera frames the pots into the free area with a view offset.
- Maximise applies to all visible windows; entering focus mode closes the side panel, leaving it restores the panel.
- Every terminal is an agent. A shell tab in an agent's worktree can come later.
- Side panel: Agents, Issues, Branches, one fixed width of about 400 px.
- Issue list is the MVP entry; 3D seed packets come later. Priority flag dropped.
- In the prototype: clicking a pot replaces the visible terminal, shift-click or "Open beside" adds a second one. Not yet in the layout page.

## Overview agent and larger table (2026-10-07)

Proposed by Georgios, worked out in the same session. Not agreed by the team yet.

- A chat with an overview of all agents: what each has done, its status, where the whole is going. Later possibly an orchestrator.
- Built as one more Claude Code session in the repo root, without a pot, not as our own chat UI over the API. It reuses the window, terminal, spawning and attention parts. A custom chat would fit the 400 px side panel, but needs an API key, context assembly and streaming; a Claude Code terminal needs about 650 px, so it lives in the main area.
- A beetle button on the rail opens it maximised (Focus this). After that it is an ordinary window.
- In the scene: a beetle carved into the front edge of the table, with emissive states. Chosen over a beetle statue behind the pots: cheaper (a decal, no model), always in the camera's frame, and its glow can change with the state.
- The table grows: pots at the back, a front strip for seed packets and the carving.
- Priority: should-have, decide at the end of week 2. Contracts and store allow an agent without a pot from day one.
- Changed: `concept/v3_layout.html` (rule R12, states S17-S19, components, tickets N13 and N14, open questions), `concept/v3_planter-grid.md`, the slide deck. The 3D prototype and its screenshots still show the old table.
